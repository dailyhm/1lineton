# overflow AI 파트 소개

overflow은 개발 학습자가 **정답을 바로 보지 않고 스스로 생각한 뒤, AI의 관점과 비교하며 배우는** 서비스입니다.


## 1. AI 파트의 역할

AI는 문제를 대신 풀어 주는 도구가 아니라 **설명과 힌트를 제공하는 학습 보조자**입니다.

| 하는 일 | 하지 않는 일 |
|---|---|
| 질문의 핵심을 제목·요약으로 정리 | 정답이나 완성 코드를 먼저 제시 |
| 생각할 방향(선택지)과 단계별 힌트 제공 | 확인되지 않은 원인을 하나로 단정 |
| 사용자의 생각을 AI 관점과 비교해 분류 | 사용자의 생각을 점수·등급으로 평가 |
| 부족한 개념을 쉬운 설명과 예시로 보완 | 코드를 실행했다고 주장하거나 결과를 지어냄 |

## 2. 기능별 동작

AI 파트는 네 가지 기능을 제공하며, 각 기능은 `prompts/`의 프롬프트와 `*_schema.json`의 출력 구조로 정의됩니다.

### 2-1. 질문 생성 (`prepare_question`)
사용자가 질문(최대 2,000자)과 코드(최대 6,000자), 질문 유형을 입력하면 한 번의 호출로 아래를 만듭니다.

- **공개 데이터(프론트 전달):** `chat_title`(50자 이내), `chat_summary`(80자 이내), `choices`(1~3개)
- **비공개 데이터(서버 보관):** `hints` 2개, `guidance` 2세트(`look_at` + `try_this`), `reference_answer`

질문 유형은 개념 이해(`CONCEPT`), 디버깅(`DEBUGGING`), 문제 해결 접근(`PROBLEM_SOLVING`), 설계 판단(`DESIGN`) 네 가지입니다.

### 2-2. 단계별 힌트·안내 제공 (`get_hint_text`, `get_guidance`)
질문 생성 때 미리 만들어 둔 내용을 1단계, 2단계 순서로 하나씩 공개합니다. 추가 AI 호출은 없습니다.

- **힌트 1:** 사고 방향만 제시. 정의, 알고리즘·해법 이름은 말하지 않습니다.
- **힌트 2:** 문제 구조를 구체화하되 핵심 용어와 정답 코드 이름은 공개하지 않습니다.
- **안내:** 살펴볼 곳(`look_at`)과 직접 해 볼 행동(`try_this`)을 함께 제시합니다. 예: F12 Console 확인, `console.log()` 실행 순서 확인, StackTrace의 파일명·줄 번호 확인.

### 2-3. 관점 비교 (`compare`)
사용자가 자신의 생각(30~4,000자)을 쓰면, 비공개 기준 답변과 비교해 다섯 가지로 분류합니다.

| 분류 | 의미 |
|---|---|
| `common` | AI 관점과 일치하고 타당한 부분 |
| `supplement` | 질문에 답하기 위해 추가로 필요한 정보 |
| `unique` | 기준 답변과 달라도 기술적으로 타당한 사용자만의 관점 |
| `error` | 질문 조건이나 확립된 사실과 명백히 충돌하는 부분 (검증 방법 포함) |
| `judgment_hold` | 의미가 모호하거나 정보가 부족해 판단하기 어려운 부분 (되묻는 질문 포함) |

- 모호하다는 이유만으로 오류로 분류하지 않고, 판단 가능한 부분은 먼저 판단합니다.
- 사용자의 의도를 임의로 만들어내지 않습니다.
- 인용(`user_quote`)이 사용자 원문에 없으면 해당 항목만 제외하고 나머지는 유지합니다.

### 2-4. 기초 학습 (`basic_learning`)
부족한 개념을 `summary`(핵심 요약), `example_code`(예시), `observe`(먼저 관찰해요), `change`(그다음 바꿔요) 네 필드로 안내합니다.

## 3. 사용자 흐름

```
질문 입력 → [AI] 제목·요약·선택지 생성 → 사용자가 먼저 자기 생각 작성
          → (필요 시) 힌트 1 → 힌트 2 / 안내 1 → 안내 2
          → [AI] 생각 비교 분석 → (필요 시) [AI] 기초 학습
```

## 4. 안정성과 안전 장치

- **JSON 출력 고정:** Gemini JSON 모드와 response schema를 쓰고, 서버에서 한 번 더 구조를 검증합니다.
- **호출 제한:** 모델 호출당 15초 제한, 실패 시 최대 2회 재시도(최초 포함 총 3회).
- **민감정보 마스킹:** API 키, 비밀번호, 토큰, 개인 키 등을 `[REDACTED]`로 바꾼 뒤 AI에 전달합니다.
- **프롬프트 보안 지시:** 입력 속 지시문을 명령으로 따르지 않고 분석 대상으로만 취급하도록 지시합니다. 이는 **프롬프트 지시로 부적절한 응답을 방지하려는 것이며, 모든 경우를 완벽하게 차단한다고 보장하지는 않습니다.**
- **범위 밖 질문:** 개발과 무관한 질문은 개발 맥락을 지어내지 않고 개발 학습 질문이 아님을 알립니다.

## 5. 데이터 저장

질문·코드 원문은 AI 호출 기록 테이블에는 남지 않지만, 서비스 DB에는 저장됩니다.
AI 모듈 자체는 DB와 비동기 작업 상태를 관리하지 않으며, 저장은 백엔드가 담당합니다.


## 6. 파일 구조

| 파일 | 설명 |
|---|---|
| `deveil_ai.py` | AI 모듈 본체(프롬프트 조립, 호출, 재시도, 검증) |
| `prompts/` | 질문 생성, 비교 분석, 기초 학습 프롬프트 |
| `question_schema.json`, `comparison_schema.json`, `learning_schema.json` | 출력 구조 |
| `api.py` | 테스트용 FastAPI 서버 (운영 백엔드는 모듈을 직접 import) |
| `evaluations/`, `tests/` | 평가 데이터와 테스트 |
