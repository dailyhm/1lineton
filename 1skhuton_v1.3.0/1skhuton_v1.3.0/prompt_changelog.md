# Prompt changelog

## v1.2.0 — 2026-11-09
- 첫 질문에서 사이드바에 사용할 `chat_title`과 `chat_summary` 생성 추가.
- 질문 생성 힌트 구조를 `hints`에서 `guidance`로 통합.
- `guidance` 한 항목에 `look_at`(짧은 관찰 지점)과 `try_this`(구체적인 행동 안내)를 함께 포함.
- 공개 데이터는 제목·요약·선택지만 포함하고, 안내와 기준 답변은 서버 내부에 보관.
- 질문 유형 4개(CONCEPT / DEBUGGING / PROBLEM_SOLVING / DESIGN)만 허용.
- 재시도 정책을 최초 호출 포함 최대 3회에서 최초 호출 후 최대 2회 재시도(총 3회)로 변경.
- 질문 최대 2,000자, 코드 최대 6,000자 제한 유지.

## v1.1.0 — 2026-11-09
- 비교 분석의 모든 항목에 title 추가.
- judgment_hold를 단일 객체에서 배열로 변경.
- 기초 학습 출력 4개 필드(summary, example_code, observe, change)로 변경.
- [REDACTED] 의미를 보안 규칙에 명시.
- Gemini JSON mode 및 response schema 적용.
- 호출당 15초 제한, 잘못된 user_quote 항목만 제외하도록 변경.

## R2 2차 요청 정합성 — 2026-11-12
- 질문 생성 스키마에서 choices 3개, guidance 2개를 명시하고 hints 출력 금지 및 비공개 경계를 강화.
- 비교 프롬프트에서 supplement와 judgment_hold의 빈 user_quote 허용을 명시.
- 기초 학습의 기존 네 필드와 네 가지 화면 표시 의미를 보강. 10개 화면별 새 키는 추가하지 않음.

## 2026-11-14 — 평가 데이터셋 기반 프롬프트 보완
- `comparison_v1.1.0.txt`: 사용자 생각을 의미 단위로 분리하고, 모호한 일부만 `judgment_hold`로 처리하도록 명시.
- `comparison_v1.1.0.txt`: 기술적으로 타당한 대안과 적용 한계의 판정 기준을 보강(`unique` / `error` 구분).
- `comparison_v1.1.0.txt`: 오류 항목의 `how_to_check`에 실행 가능한 검증 절차, 예상 결과 및 의미를 포함하도록 보강.
- `question_v1.2.0.txt`: 힌트 1·2의 정보 공개 단계를 구체화하고 Q-D1~Q-D5별 유도·검증 지침을 추가.
- `learning_v1.1.0.txt`: 관찰 및 실습에 직접 행동, 예상 결과, 결과 해석을 포함하도록 보강.
- JSON 스키마와 API 계약은 변경하지 않음. 코드, 재시도 정책, 보안 처리 및 백엔드 로직도 변경하지 않음.


## 심사 설명 정합성 및 선택지 범위 보완
- 질문 생성 선택지 수를 정확히 3개에서 1~3개로 변경하고, 개수를 채우기 위한 부정확한 선택지 생성을 금지.
- AI는 질문 유형·사용자 수준에 맞는 설명과 힌트를 제공해 주도적 사고를 돕는 역할로 명확화. 정답 선공개 시점은 서비스 코드가 제어한다고 구분.
- 입력 속 지시문에 대해서는 따르지 않도록 프롬프트로 지시한다고 표현하고, 완벽한 차단 보장은 하지 않도록 보안 문구 완화.
- AI 호출 테이블과 서비스 전체 DB의 저장 범위를 구분하도록 문서화.
- 사용 모델은 최종 결정 전으로 표기하고, 특정 모델을 확정하지 않음.
