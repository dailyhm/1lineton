# Deveil AI 프롬프트 구조 v1.3.0

## 파일
- `question_v1.2.0.txt`: 첫 질문의 사이드바용 제목·요약, 선택지, 관찰 지점과 행동 힌트, 서버 전용 기준 답변 생성
- `comparison_v1.1.0.txt`: 사용자 생각과 기준 답변의 관점 비교
- `learning_v1.1.0.txt`: 초보자용 기초 학습 설명

## 질문 생성 출력
- `chat_title`: 첫 질문을 대화방 제목처럼 요약(최대 50자)
- `chat_summary`: 질문의 핵심 확인 대상을 자연스러운 짧은 구절로 요약(최대 80자)
- `choices`: 사고 방향 선택지 1~3개 (해법 이름 없이 생각할 지점만 표시)
- `hints`: 단계별 힌트 문자열 2개(서버 내부 보관, 단계별 제공)
- `guidance`: 두 단계. 각 항목은 `look_at`(간단한 관찰 대상) + `try_this`(구체적인 행동 지침)
- `reference_answer`: 서버 내부 비교 분석용 기준 답변

`guidance`는 한 묶음으로 사용자에게 표시합니다. `look_at`은 어디를 볼지, `try_this`는 그 위치에서 무엇을 직접 해볼지 안내합니다. 두 요소를 별도 기능이나 별도 목록처럼 분리하지 않습니다.

## 코드에서 치환하는 토큰
`{{{{SECURITY_RULE}}}}`, `{{{{SELECTED_TYPE}}}}`, `{{{{QUESTION}}}}`, `{{{{CODE}}}}`, `{{{{QUESTION_SCHEMA}}}}`, `{{{{QUESTION_TYPE}}}}`, `{{{{ORIGINAL_THOUGHT}}}}`, `{{{{REFERENCE_ANSWER}}}}`, `{{{{COMPARISON_SCHEMA}}}}`, `{{{{LEARNING_SCHEMA}}}}`를 임의로 이름 변경하거나 삭제하지 마세요.

## 입력 제한 및 보안
- 질문: 최대 2,000자
- 코드: 최대 6,000자
- 질문 유형: `CONCEPT`, `DEBUGGING`, `PROBLEM_SOLVING`, `DESIGN`
- `[REDACTED]`는 민감정보가 마스킹된 표시이며 원래 값을 추측하거나 복원하지 않습니다.
- 기준 답변과 `guidance`는 프론트에 일괄 전달하지 않고 서버에서 보관합니다.

## R2 2차 요청 확인
- 질문 생성은 실제 `question_schema.json` 및 `deveil_ai.py` 기준으로 `chat_title`, `chat_summary`, `choices` 1~3개, `hints` 2개, `guidance` 2개, `reference_answer`를 생성합니다. `question_type`, `example_sentence`는 출력하지 않습니다.
- 공개 필드는 제목·요약·선택지이며 `hints`, `guidance`, `reference_answer`는 서버 내부 데이터입니다. `hints`와 `guidance`는 단계별 전용 API에서 제공됩니다.
- 비교 분석의 `supplement`와 `judgment_hold`는 인용할 사용자 문장이 없으면 `user_quote`를 빈 문자열로 둘 수 있습니다.
- 기초 학습은 기존 네 필드(`summary`, `example_code`, `observe`, `change`)를 유지합니다.

## 프롬프트 품질 개선 — 2026-11-14
- 비교 분석: 모호한 생각을 의미 단위로 분리하고, 판단 가능한 부분과 판단 보류 부분을 각각 처리하도록 보강.
- 비교 분석: 기술적으로 타당한 대안은 기준 답변과 달라도 `unique`로 인정하고, 적용 조건·한계를 함께 설명하도록 보강.
- 비교 분석: 검증 가능한 `error`에는 실제 실행·로그·개발자 도구 등을 이용한 확인 절차를 `how_to_check`에 작성하도록 보강.
- 질문 생성: 힌트 1과 힌트 2의 정보 공개 단계를 분리하고, Q-D1~Q-D5 유형별 조기 정답 노출 방지 및 직접 검증 행동을 보강.
- 기초 학습: 관찰·실습 단계에서 실행 행동, 예상 결과 및 결과의 의미를 설명하도록 보강.
- JSON 스키마, 필드명, 필수 필드 및 API 동작은 변경하지 않았습니다.

## AI 역할, 보안, 데이터 저장 고지
- AI는 정답이나 완성 코드를 제공하지 않고 **설명과 힌트를 제공**하는 역할입니다.
- 보안 규칙은 **프롬프트 지시로 부적절한 응답을 방지**하도록 한 것이며, 모든 경우를 완벽하게 차단한다고 보장하지 않습니다.
- 질문·코드 원문은 AI 호출 기록 테이블에는 남지 않지만, 서비스 DB에는 저장됩니다.

## 칩·힌트 작성 기준 (QA 반영)
- 칩: 정답·해법·알고리즘·API 이름을 쓰지 않고 생각할 지점만 가리킵니다. 같은 관점은 하나로 합칩니다.
- 힌트 1: 정의·알고리즘 이름을 말하지 않습니다. 힌트 2: 핵심 용어와 정답 코드·함수 이름을 공개하지 않습니다.
- 기준 답변: 유형별 구성(개념=정의·근거·예시 / 디버깅·문제 해결=원인·근거·확인 방법 / 설계=판단 기준·트레이드오프)을 따릅니다.
- 개발과 무관한 질문은 개발 맥락을 지어내지 않고 개발 학습 질문이 아님을 알립니다.
